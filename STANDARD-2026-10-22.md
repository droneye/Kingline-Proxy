# Единая конфигурация по работающей Дании

Владелец сообщил, что Дания сейчас работает лучше всего, и потребовал одинаковые параметры всех нод. Германия, Дания, Турция и автоматический профиль приведены к действующему датскому подключению.

| Параметр | Значение во всех четырёх профилях |
|---|---|
| Протокол | VLESS |
| Транспорт | TCP/RAW |
| Защита / flow | REALITY / `xtls-rprx-vision` |
| Порт | 443 |
| Отпечаток | `firefox` |
| SNI / target | `www.samsung.com` / `www.samsung.com:443` |
| Keepalive | idle 60 секунд, interval 30 секунд |
| Max Time Diff | 120000 мс |
| DNS на нодах | `1.1.1.1`, `1.0.0.1`, IPv4 |
| Маршрутизация | Прямой выход с ноды, запрет служебных/частных адресов |
| XHTTP / MUX | Не используются |

Все ноды используют один config profile и один активный inbound Remnawave. Вариант AWS с Chrome и портом 36847, успевший примениться к Германии и Турции во время предыдущего запроса, удалён из hosts, активных inbound нод и личной группы. Его правило firewall также удалено. Связанные с ним записи `manual_connection` убраны из реестра.

Текущие UUID, ключи REALITY, short ID, персональная ссылка и пользовательский аккаунт сохранены. Для получения одинаковых параметров нужно обновить подписку в v2rayTun и переподключиться. Backend наследует тот же стандарт для будущих нод. При `enforce_uniform_profiles=true` он обнаруживает иной порт, SNI, fingerprint или inbound опубликованного host и возвращает `published_profile_drift`.

По последнему указанию владельца умный выбор использует Германию и Данию: обе ноды имеют `maintenance=false`. Турция временно исключена из DNS-распределения (`maintenance=true`) из-за нестабильной работы; её ручной профиль доступен. Тарифные скорости, квоты и учёт трафика сохранены. После устранения проблемы вернуть Турцию можно командой `kingline-node capacity UUID --maintenance off`. DNS не переносит уже открытый туннель; кеш клиента может сохранять старый ответ до TTL 60 секунд.

Все четыре записи подписки прошли HTTPS и UDP DNS через Xray 26.6.27 из Литвы; автоматический профиль вышел с датского IP. Проверены отклонение неверного пользователя и запрет доступа к служебной сети. Пройдены 38 автоматических тестов, включая запрет расхождения одного опубликованного профиля. Равенство конфигурации не доказывает доступность каждого IP у оператора РФ: работу Германии и Турции на телефоне ещё нужно подтвердить.

Снимок перед изменением указан в `danish-standard.json`. Итоговые отчёты: `verification-danish-standard.json`, `verification-vpn.json`, `tunnel-health.json`, `smart-dns-status.json`. Эти файлы не содержат персональной ссылки или приватного ключа. Предыдущий эксперимент сохранён для истории, его `mobile-variant.json` имеет `active=false`.

# Откат собственного HTTPS-target и проверка работоспособности VPN

Последующее решение владельца: единый стандарт Дании для всех нод и временная маршрутизация умного выбора только в Данию. Актуальное состояние — [STANDARD-2026-10-22.md](STANDARD-2026-10-22.md).

22 октября 2026 года владелец сообщил, что после перехода на `edge.kingline.online` ключи перестали подключаться. Серверные проверки предыдущего изменения проходили, но они не воспроизводили сеть пользователя. Причина отказа на телефоне не установлена: без журнала клиента и проверки из этой сети нельзя уверенно приписать его фильтрации или конкретной ошибке протокола.

Восстановлен последний профиль, который владелец ранее подтвердил как рабочий. Восстановление выполнено из `/opt/kingline-control/before-owned-target-20261022-050324`. Пользователи, UUID, ключи, short ID, лимиты, счётчики трафика, ноды и персональная ссылка сохранены.

## Действующий стандарт всех нод

| Параметр | Значение |
|---|---|
| Протокол / транспорт | VLESS / TCP (RAW) |
| Защита / flow | REALITY / `xtls-rprx-vision` |
| Порт | TCP 443 |
| Fingerprint | `firefox` |
| SNI | `www.samsung.com` |
| Target | `www.samsung.com:443` |
| Keepalive | idle 60 с, interval 30 с |
| Допустимое расхождение часов REALITY | 120 секунд |
| XHTTP / MUX | Не используются |
| Серверная маршрутизация | Запрет `geoip:private`, DNS IPv4, обычный выход в интернет |

Собственный Nginx, сертификаты в рабочем каталоге нод и правило входящего HTTP 80 удалены. Таймер `kingline-cover-maintenance.timer` отключён. A-запись экспериментального HTTPS-домена удалена; зона DNS, NS-записи и `auto.edge.kingline.online` сохранены. Защищённые архивы предыдущего состояния остаются для восстановления.

Новые ноды наследуют текущий стандарт без собственного HTTPS. Backend проверяет закреплённый target наряду с транспортом, SNI и fingerprint. Проверка подписки теперь явно сверяет выдаваемые SNI, REALITY public key и short ID с выбранной конфигурацией.

## Проверка настоящего VPN для умного выбора

`kingline-tunnel-health.timer` запускает проверку примерно через три минуты после завершения предыдущей. Для каждой опубликованной ноды создаётся временный клиент Xray 26.6.27 и проверяются реальный HTTPS-туннель, ожидаемый публичный IP и UDP DNS. Клиент завершается после проверки, временная конфигурация удаляется.

Первый сбой переводит проверку в `retrying`. Два последовательных свежих сбоя дают `excluded`, после чего контроллер DNS убирает ноду из автоматического выбора. Успешная проверка сразу сбрасывает счётчик и возвращает `healthy`. Ручной профиль не удаляется. Контроллер применяет изменения примерно за 30 секунд; клиентский DNS-кеш может удерживать ответ ещё до TTL 60 секунд.

Результат привязан к ноде, IP и текущей конфигурации, включая отпечаток реквизитов. Данные старше десяти минут и данные прежней конфигурации не используются. При недоступности обоих внешних HTTPS-сервисов проверки результаты получают статус неизвестных и не отключают все ноды. Предусмотрены запасные HTTPS- и DNS-сервисы. Независимые TCP-проверки трёх DNS-реплик продолжают работать.

Отчёт: `/opt/kingline-control/tunnel-health.json`. Для будущего фронтенда `/v1/nodes` возвращает `routing.nodes[].vpn_probe_state` и `vpn_probe_excluded`. Проверяющий модуль пока использует действующего тестового пользователя, как и проверка при установке; перед отключением этого аккаунта его нужно заменить техническим.

Проверка выполняется из Литвы и выявляет неисправности ноды/туннеля. Она не подтверждает доступность из РФ и не заменяет будущий модуль Raspberry Pi. DNS также не переносит уже открытые соединения между нодами.

## Проверки и дальнейшие изменения

Пройдены 36 автоматических тестов, в том числе исключение неисправного туннеля при доступной сети управления, восстановление после успеха, защита от устаревших результатов, сбоя общего проверочного сервиса и изменения реквизитов. Все четыре профиля рабочей подписки проверяются через HTTPS и UDP; неверный пользователь отклоняется, служебная сеть недоступна через VPN.

Отчёты: `owned-target-rollback.json`, `verification-vpn.json`, `tunnel-health.json`, `smart-dns-status.json`. Все 196 передач нагрузочной проверки прошли без ошибок: по 49 одновременных передач на каждом из четырёх профилей. Отчёт `verification-load-rollback-stable.json` характеризует Linux-клиент, а не память расширения iOS. Временный тестовый порт и контейнер после проверки удалены.

На телефоне нужно обновить существующую подписку и переподключиться. Подтверждение работоспособности после отката от владельца пока не получено. Следующий кандидат SNI/target следует проверять отдельным тестовым профилем из сети пользователя до переноса рабочей подписки.

Проверены первичные источники: [настройки REALITY](https://xtls.github.io/en/config/transports/reality.html), [эталон TCP + Vision + REALITY](https://github.com/XTLS/Xray-examples/blob/main/VLESS-TCP-XTLS-Vision-REALITY/REALITY.ENG.md), [правила маршрутизации Xray](https://xtls.github.io/en/config/routing.html). Они описывают совместимость и настройки, но не гарантируют обход фильтрации конкретного оператора.
